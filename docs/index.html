Jigoku Card builder reference

Implementing cards in Jigoku

How a card file is built, how card text becomes builder calls, and the rules the code follows: timing, chat text, testing and common mistakes.

From card text to code

A card's abilities are written with a builder: a method that names the ability, followed by one call for each part of the card text. Read the card from left to right and write the calls in the same order. Hover a line to see which part of the text it implements.

Conflict Action:
this.conflictAction('Discard a character')
Lose 3 honor.
.cost(costs.payHonor(3))
Choose a character with printed cost 2 or lower –
.target({ cardType: CardType.Character, cardCondition: (card) => card.costLessThan(3) },
discard that character.
discardFromPlay())
(Max 1 per round.)
.max(perRound(1));

The full order, as the builder expects it:

  1. The trigger: when() or aggregateWhen(), for reactions and interrupts.
  2. When and where the ability can be used: phase(), location(), condition(), playOnlyIf(), anyPlayer(), collectiveTrigger(), evenDuringDynasty(), canTriggerOutsideConflict(), conflictProvinceCondition().
  3. Costs: cost(), once per cost.
  4. Targets: target(), targetCards(), ringTarget(), select(), …
  5. Effects: game actions, if()/ifAble()/otherwise(), onAffinity(), initiateDuel(), handler().
  6. chatText().
  7. Limits and flags: limit(), max(), cannotTargetFirst(), cannotBeMirrored(), notPrinted().
  8. The next step: then(), afterwards(), thenIf(), afterwardsIf(). A step is written in the same order, without the ability's own settings.

The order is more than style: the builder fixes its types from left to right, so each call sees what the calls before it declared. A chatText() after a target() knows the target's card type; one before it doesn't. The ability builder page documents every call.

Anatomy of a card file

Every card is a class in its own file under server/game/cards/, in the folder of its pack (and clan, for newer packs). The file is named after the card in PascalCase: server/game/cards/01-Core/Assassination.ts. The card loader picks up every file in these folders; there is nothing to register.

import DrawCard from '../../DrawCard.js';
import { CardType } from '../../Constants.js';
import * as costs from '../../costs/index.js';
import { perRound } from '../../AbilityLimit.js';
import { discardFromPlay } from '../../GameActions/GameActions.js';

export default class Assassination extends DrawCard {
    static id = 'assassination';

    setupCardAbilities() {
        this.conflictAction('Discard a character')
            .cost(costs.payHonor(3))
            .target({
                cardType: CardType.Character,
                cardCondition: (card) => card.costLessThan(3)
            }, discardFromPlay())
            .max(perRound(1));
    }
}
  • The base class follows the card type: DrawCard for characters, attachments, events and holdings; ProvinceCard, StrongholdCard and RoleCard for those. Some families have their own base, such as TokenCard or ProvinceAttachment (see card helpers).
  • static id is the card's id in the card data (test/json/Card/<id>.json), which also holds the card's text. A card without a class still works with its printed stats and keywords, but has no abilities.
  • setupCardAbilities() declares every ability once, when the card is created. Don't keep game state in it; everything that changes during a game goes through the context and the game actions.
  • Imports: game actions from GameActions/GameActions.js, effects from effects.js, costs as import * as costs from '…/costs/index.js', limits from AbilityLimit.js, enums from Constants.js, chat templates (msg) from GameChat.js. Import types with import type; the linter enforces it.
  • Keywords (Covert, Sincerity, Pride, Restricted, …) come from the card data; you don't declare them.

The context

Every callback gets context: the ability being resolved. The fields you will use most:

FieldWhat it holds
context.sourceThe card the ability is on, typed as the card's own class.
context.playerThe player using the ability.
context.targetThe card chosen by the target named target (a target without a name).
context.targets.nameThe card(s) chosen by the target with that name.
context.ring / context.rings.nameChosen rings.
context.select / context.selects.name.choiceThe label chosen in a select.
context.costs.keyWhat a cost recorded once it was paid (see costs).
context.eventFor reactions and interrupts: the event that triggered the ability, typed by the when() keys.
context.gameThe game, for queries such as isDuringConflict().

Conditions and target conditions are also checked before anything is chosen or paid, to decide whether the ability can be used at all. At that time context.costs is empty and later targets aren't chosen yet: handle undefined. The context reference lists every field and when it is set.

Timing: costs, targets, effects

An ability resolves in a fixed order: the player pays its costs, then chooses its targets, then the effects resolve. The builder follows the Rules Reference Guide here, and so should a card's code.

If the additional cost cannot be paid, the game action cannot be initiated. All costs are paid simultaneously, including additional ones.
Costs
The word "choose" indicates that one or more targets must be chosen in order to resolve an ability.
Choose

So "choose a character" is a target(), chosen when the ability initiates, and the ability can't be used without a legal one. A choice made while the effect resolves ("…, then choose") is a game action such as selectCard or chooseAction.

If a selection is required before the effect of the ability resolves (i.e., before the dash), the selection is made during the same timing step in which targets are chosen. If a selection is indicated after the dash of an ability's text, that selection is made during the resolution of the effect.
Select

Before the dash: select() on the builder. After the dash: the chooseAction game action.

Then, if you do, afterwards

  • "If you do, …" is then(): the next step runs only if the step before it resolved in full.
  • A plain "Then, …" only sets the order: afterwards(), which runs either way. (The Emerald Legacy rules have a success rule only for "to"; their errata turn conditional "Then"s into "If you do".)
  • "Then, if …" is thenIf((context) => …); an "If …" read after the step without "then" is afterwardsIf((context) => …).
  • A step's context holds the targets chosen so far, so context.target still names the card chosen in the first step.

If, if able, otherwise

  • "If X, do A. Otherwise, do B." is .if((context) => X).a().otherwise().b(). Without otherwise(), nothing happens when the condition fails. Right after a card target without game actions of its own, the branches belong to that target: they resolve on the chosen card, and only cards a branch can affect are selectable.
  • "Do A, if able. Otherwise, do B." is .ifAble().a().otherwise().b(): no condition, A resolves when it can. otherwise() is required, and the branches always stay on the ability, so their actions name their targets.

Cancelling and limits

If the effects of an ability are canceled, the ability is still considered to have been used, and any costs have still been paid.
Cancel

Costs are therefore paid before the effects can be cancelled, and they stay paid. Limits count a use even when the effects are cancelled. limit() is the card's "Limit X per …"; max() is "Max X per …", which counts across all copies of the card.

Chat text

When an ability resolves, the chat says what happened: player1 plays Assassination, losing 3 honor to discard Doji Whisperer. The part after "to" comes from the ability (a card ability reads "uses", an event "plays"; the costs come before "to"):

  • By default it is built from the game actions' own texts, joined ("bow Doji Whisperer and draw 1 card"). Often that is all you need.
  • chatText('format', args?) replaces it: {0} is the target (or the source), {1} onwards are the entries args(context) returns.
  • chatText((context) => msg`…`) is a template; cards, players and rings in it are shown as such.
  • Per choice: a select choice { action, chatText } gives the line for that choice; the ability then has no chatText() of its own.

The chat formats game objects and some words, so they must reach it as values, not as text:

  • Cards, players and rings go in a msg template or into {N} arguments. Built into a plain string (`… ${card.name}`, '… ' + player.name), they lose their formatting.
  • The words military and political, element names and clan names become icons only as values on their own: msg`+2${'military'}`, not '+2 military'.
// wrong: the player's name is plain text
.chatText((context) => `place it on top of ${context.event.card.owner.name}'s conflict deck`)
// right: a msg template
.chatText((context) => msg`place a fate from ${context.target.controller}'s fate pool on ${context.target}`)
// right: game objects as arguments
.chatText('place a fate from {1}\'s fate pool on {0}', (context) => [context.target.controller])

Conventions: a game message begins with the player doing the action, uses the present tense, and doesn't end in punctuation. Prompt titles say "Choose a <card type>" where they can. Any change to an existing chat line needs approval: chat is what players read.

Examples of more complex cards

"If you do": Ujiaki's Offer

// Action: During a [political] conflict, choose a participating character with printed cost equal to or lower
// than that of another participating character you control - place 1 fate on the chosen character.
// If you do, bow it, move it home, and dishonor it.
this.conflictAction('Place a fate on a participating character, bow it, move it home, and dishonor it', { conflictType: ConflictType.Political })
    .target({
        cardType: CardType.Character,
        cardCondition: (card, context) => card.isParticipating() && context.player.cardsInPlay.some((myCard) => (
            myCard !== card && myCard.isParticipating() && (myCard.printedCost ?? 0) >= (card.printedCost ?? 0)))
    }, placeFate())
    .chatText('place a fate on {0} then bow, dishonor, and move them home')
    .then()
    .bow((context) => ({ target: context.target }))
    .dishonor((context) => ({ target: context.target }))
    .sendHome((context) => ({ target: context.target }));

The fate is the target's own action; the rest is a then() step, so it only happens when the fate was placed. The step reads the chosen character as context.target.

A duel: Doji Reiha

// Conflict Action: Initiate a [political] duel against a character your opponent controls of their choice -
// resolve the duel. Honor each contestant character (in this duel). Then, the controller of the winner may
// choose to move each contestant home.
this.conflictAction('Initiate a duel that honors participants and move loser home')
    .initiateDuel(() => ({
        type: DuelType.Political,
        opponentChoosesDuelTarget: true,
        gameAction: (duel) => sequential([
            honor({ target: duel.participants }),
            chooseAction({
                player: duel.winnerController,
                choices: {
                    'Move all duel participants home': sendHome({ target: duel.participants }),
                    'Do nothing': noAction()
                }
            })
        ]),
        onTie: (duel) => honor({ target: duel.participants })
    }));

gameAction resolves after a duel with a winner, onTie after a tie. The choice is made while the effect resolves ("Then, … may choose"), so it is a chooseAction for the winner's controller.

If able, otherwise: Calling in Favors

// Action: Dishonor a (friendly) character. Choose an opponent's attachment – take control of that attachment
// and attach it to that character, if able. Otherwise, discard the attachment.
this.action('Take control of an attachment')
    .cost(costs.dishonor())
    .target({
        cardType: CardType.Attachment,
        controller: Players.Opponent
    })
    .ifAble()
    .attach((context) => ({
        target: context.costs.dishonor,
        attachment: context.target,
        takeControl: true
    }))
    .otherwise()
    .discardFromPlay((context) => ({ target: context.target }));

The dishonored character is a cost, recorded in context.costs.dishonor. Attaching fails when the rules don't allow it (for example a second copy of the same attachment), and then the attachment is discarded.

A choice before the dash: Hero of Three Trees

// Action: During a conflict in which this character is participating, if you have fewer cards in your hand
// than your opponent, select one - either gain 1 honor, or the attacked province gets -1 strength until the
// end of the conflict (to a minimum of 0).
.select({
    'Gain 1 honor': { action: gainHonor(), chatText: 'gain 1 honor' },
    'Lower attacked province\'s strength by 1': {
        action: selectAttackedProvince({ … }),
        chatText: 'reduce the strength of an attacked province by 1'
    }
})

"Select one" before the dash is a select(); each choice brings the chat line for when it's chosen.

A granted ability: Kagi-nawa

// If attached character has the Shinobi trait, it gains: "Conflict Action: Choose a character with printed
// cost 2 or lower - move that character to this conflict."
this.whileAttached({
    match: (card) => card.hasTrait('shinobi'),
    effect: gainAbility.conflictAction('Move a character to the conflict', (ability) => ability
        .target({
            cardType: CardType.Character,
            controller: Players.Any,
            activePromptTitle: 'Choose a character with printed cost 2 or lower to move in',
            cardCondition: (card) => (card.printedCost ?? 0) <= 2
        }, moveToConflict())
        .chatText('hook {0} and drag them into the conflict'))
});

The granted ability is written with the same builder; inside it, context.source is the character that gained it, not the attachment.

Testing a card

Every card gets a spec in test/server/cards/, mirroring the card's folder: test/server/cards/01-Core/Assassination.spec.js. A spec sets up a game in the state the card needs, plays it, and checks the result.

describe('Assassination', function () {
    integration(function () {
        beforeEach(function () {
            this.setupTest({
                phase: 'conflict',
                player1: {
                    honor: 10,
                    inPlay: ['doji-challenger'],
                    hand: ['assassination']
                },
                player2: {
                    inPlay: ['doji-whisperer']
                }
            });
            this.whisperer = this.player2.findCardByName('doji-whisperer');
            this.noMoreActions();
            this.initiateConflict({ attackers: ['doji-challenger'], defenders: ['doji-whisperer'] });
            this.player2.pass();
        });

        it('discards a character with printed cost 2 or lower', function () {
            this.player1.clickCard('assassination');
            expect(this.player1).toBeAbleToSelect(this.whisperer);
            this.player1.clickCard(this.whisperer);
            expect(this.whisperer.location).toBe('dynasty discard pile');
            expect(this.player1.honor).toBe(7);
            expect(this.getChatLogs(3)).toContain('player1 plays Assassination, losing 3 honor to discard Doji Whisperer');
        });
    });
});

setupTest options

OptionMeaning
phaseThe phase the test starts in: 'setup', 'dynasty', 'draw', 'conflict', 'fate'. For draw and fate, the action windows of that phase are turned on.
gameModeA GameMode (Stronghold by default); Emerald turns on its rules, such as one copy of an attachment per character.
player1, player2Each player's cards: inPlay (ids, or { card, fate, honor, bowed, covert, attachments }), hand, conflictDeck, conflictDiscard, dynastyDeck, dynastyDiscard, provinces, strongholdProvince, stronghold, role, faction, fate, honor, and the deck sizes conflictDeckSize/dynastyDeckSize.
skipAutoSetup, skipAutoFirstPlayerStop before the stronghold provinces or the first player are chosen.

Driving the game

  • this.player1.clickCard(card), clickPrompt('Text'), clickRing('air'), clickMenu(card, 'Text'), pass(), passConflict(), playAttachment(attachment, target), playCharacterFromHand(card, fate), placeCardInProvince(card, location), moveCard(card, location).
  • this.noMoreActions() passes both players' action windows; this.initiateConflict({ type, ring, province, attackers, defenders }) declares a conflict; this.flow.finishConflictPhase() and this.advancePhases(phase) move on.
  • Finding cards: findCardByName(id, location?), filterCardsByName(id).
  • Matchers: toHavePrompt(title), toHavePromptButton(text), toHaveDisabledPromptButton(text), toBeAbleToSelect(card), toBeAbleToSelectRing(element).
  • Chat: this.getChatLogs(n) returns the last n lines.

Rules the specs follow:

  • A card that searches the top X cards of a deck is tested with more than X cards in the deck, and the spec checks that the rest stays untouched.
  • A bug in the engine (rather than in one card) gets its regression spec in test/server/integration/, not in a card's spec.
  • An ability with a select() before the dash always shows its prompt when it is used, with "Pay costs first" and "Cancel", even when only one choice is legal. The spec clicks the choice (clickPrompt('Move into conflict')) before it checks anything.
  • A spec should fail without the fix it tests. Run a subset with npm run jasmine -- <spec paths>.

Checks you don't write

Many card texts start with a condition the engine already enforces. A condition() or cardCondition that repeats it only adds noise, and on province actions it can be wrong.

Already checkedSo don't addKeep a check when
conflictAction() requires a conflict and, on a character, its participation.isDuringConflict(), context.source.isParticipating()The text adds more, such as a ring or a player state.
A province's action() works only during a conflict at that province (conflictProvinceCondition changes which).isConflictProvince() or isDuringConflict() in its conditionNever for the province itself. Keeper of Secret Names resolves a province's action with the province check switched off (Blocker.WrongProvince); a condition repeating it would stop Keeper.
initiateDuel() with requiresConflict (the default) needs a participating challenger and duel target.isDuringConflict(), the source's isParticipating()The duel needs a conflict of one type: isDuringConflict(ConflictType.Military).
A target whose cardCondition needs isParticipating(), isAttacking() or isDefending(): no card passes without a conflict.isDuringConflict() on the abilityIt checks the conflict type; or it guards an access to game.currentConflict; or the ability has no target to filter (its actions compute their own targets), so nothing else stops the costs being paid outside a conflict.
sendHome only affects participating characters, moveToConflict only characters at home during a conflict.isParticipating() / !isParticipating() in that target's cardCondition, isDuringConflict() on the abilityThe target has no game action of its own and a later target's action reads it (context.targets.character): its condition is the only filter.

Two checks that look redundant are not. isDuringConflict() in a when() decides when the ability triggers, which nothing else checks. A province's persistentEffect has no province check, so "while this province is being attacked" needs condition: (context) => context.source.isConflictProvince().

Common mistakes

  • Changing the game state directly (card.bowed = true, player.moveCard(…), context.target = …) instead of through game actions. Direct changes skip events, so reactions, interrupts, restrictions and chat never see them.
  • A handler() where a game action exists. A handler is the last resort for one-off logic; it can't be cancelled or checked for legality.
  • .gameAction(x(…)) where a shortcut exists: write .x(…).
  • A choice after the dash written as a target (or the other way round). See timing.
  • "Then" as then() when the card has no "if you do": that's afterwards().
  • Repeating a default: { target: context.source } on a card action that isn't under a target, or player: Players.Self.
  • Reading context.costs in a condition without handling undefined: it is only set once the costs are paid.
  • this.game or this.x inside a callback instead of context.game and context.source: the context is the ability being resolved, which matters for copies and gained abilities. Calling a helper method of the card's own class (this.countBushi(context)) is fine.
  • A conditional() for "Select one –": it picks a branch by itself without asking the player. A choice the player makes is a select() (before the dash) or chooseAction (after it).
  • Checking what the engine already checks, such as isDuringConflict() next to a target that must be participating. See checks you don't write.
