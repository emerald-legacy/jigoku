Jigoku Card builder reference

Implementing cards in Jigoku

How a card file is built, how card text becomes builder calls, and the rules the code follows: timing, chat text, testing and common mistakes.

Start here; the other pages are references (see reading the reference pages).

From card text to code

An ability is a card method that starts and names it, followed by one builder call per part of the card text, in the order of the text. Hover a line to see which part it implements.

Conflict Action:
this.conflictAction('Discard a character')
Lose 3 honor.
.cost(costs.payHonor(3))
Choose a character with printed cost 2 or lower –
.target({ cardType: CardType.Character, cardCondition: (card) => card.costLessThan(3) },
discard that character.
discardFromPlay())
(Max 1 per round.)
.max(perRound(1));

The full order of the calls:

  1. The trigger, for reactions and interrupts: when() or aggregateWhen().
  2. When and where the ability can be used: phase(), location(), condition(), ifCondition(), playOnlyIf(), anyPlayer(), collectiveTrigger(), evenDuringDynasty(), canTriggerOutsideConflict(), conflictProvinceCondition().
  3. Costs: cost(), once per cost.
  4. Targets: target(), targetCards(), ringTarget(), select(), selectFrom(), abilityTarget(), elementTarget(), tokenTarget().
  5. Effects: game actions (a shortcut such as .bow(), or gameAction()), if()/ifAble()/otherwise(), onAffinity(), initiateDuel(), handler(), onResolve().
  6. Chat: chatText() on the ability, message() on a step.
  7. Limits and flags: limit(), max(), cannotTargetFirst(), firstPlayerChoosesFirst(), cannotBeMirrored(), attachmentText().
  8. What comes next: a step with then(), afterwards(), thenIf() or afterwardsIf(), or mayResolveAgain(). A step is written in the same order, without the ability's own settings.

The order matters: the builder fixes its types left to right, so a chatText() after a target() knows the target's card type and one before it doesn't. Every call is on the ability builder page.

Anatomy of a card file

Every card is a class in its own PascalCase file under server/game/cards/<pack>/ (plus a clan folder in newer packs), e.g. server/game/cards/01-Core/Assassination.ts. The loader registers each default export by its static id; there is nothing else to register. Files directly in server/game/cards/ and files starting with _ are shared helpers, not cards.

import DrawCard from '../../DrawCard.js';
import { CardType } from '../../Constants.js';
import * as costs from '../../costs/index.js';
import { perRound } from '../../AbilityLimit.js';
import { discardFromPlay } from '../../GameActions/GameActions.js';

class Assassination extends DrawCard {
    static id = 'assassination';

    override setupCardAbilities() {
        this.conflictAction('Discard a character')
            .cost(costs.payHonor(3))
            .target({
                cardType: CardType.Character,
                cardCondition: (card) => card.costLessThan(3)
            }, discardFromPlay())
            .max(perRound(1));
    }
}

export default Assassination;
  • The base class follows the card type: DrawCard for characters, attachments, events and holdings; ProvinceCard, StrongholdCard and RoleCard for those. Some families have their own base, such as TokenCard or ProvinceAttachment (see card helpers).
  • static id is the card's id in the card data (test/json/Card/<id>.json, which also holds its text). A card without a class keeps its printed stats and keywords but has no abilities.
  • setupCardAbilities() (marked override, as the compiler requires) declares every ability once, when the card is created. Keep no game state there; game changes go through the context and game actions.
  • Imports: game actions from GameActions/GameActions.js, effects from effects.js, costs as import * as costs from '…/costs/index.js', limits from AbilityLimit.js, enums from Constants.js, chat templates (msg) from GameChat.js. Import types with import type; the linter enforces it.
  • Keywords (Covert, Sincerity, Pride, Restricted, …) come from the card data. Only the two with a value are declared: this.legendary(x) and this.tutored('X').

The context

Every callback gets context, the ability being resolved. The common fields:

FieldWhat it holds
context.sourceThe card the ability is on, typed as the card's own class.
context.playerThe player using the ability.
context.targetThe card chosen by the unnamed target; several cards are in context.targets.target.
context.targets.nameThe card(s) chosen by the target with that name.
context.ring / context.rings.nameChosen rings.
context.select / context.selects.name.choiceThe label chosen in a select.
context.costs.keyWhat a cost recorded once it was paid (see costs).
context.eventFor reactions and interrupts: the event that triggered the ability, typed by the when() keys.
context.gameThe game, for queries such as isDuringConflict().

Conditions and target conditions also run before anything is chosen or paid, to decide whether the ability is usable. Then context.costs is empty and later targets are unset: handle undefined. All fields and when they are set: context reference.

Timing: costs, targets, effects

Per the Emerald Legacy Rules Reference Guide (RRG), an ability pays its costs, then chooses targets, then resolves its effects.

The UI offers the targets first with a "Pay costs first" button (not when a cost depends on a target, e.g. playing an attachment); targets are rechecked after the costs. When a target depends on a cost, use cannotTargetFirst().

If the additional cost cannot be paid, the game action cannot be initiated. All costs are paid simultaneously, including additional ones.
Costs
The word "choose" indicates that one or more targets must be chosen in order to resolve an ability.
Choose

"Choose a character" is a target(): chosen on initiation, and the ability can't be used without a legal one. A choice during resolution ("…, then choose") is a game action such as selectCard or chooseAction.

If a selection is required before the effect of the ability resolves (i.e., before the dash), the selection is made during the same timing step in which targets are chosen. If a selection is indicated after the dash of an ability's text, that selection is made during the resolution of the effect.
Select

Before the dash: select() on the builder. After the dash: the chooseAction game action.

Then, if you do, afterwards

  • "Then, …" and "If you do, …" are then(): the next step runs only if the step before it resolved in full (designer ruling, 2026-10-20).
  • "Then, if …" and "If you do, and …" are thenIf((context) => …): the step before must have resolved in full, and the condition must hold.
  • A sentence without "then" that must follow the effect ("Shuffle.", "If it is now …") is afterwards() or afterwardsIf(), which run either way. Anything else is simultaneous (RRG): keep it in one step, so a "may" (optional(), onAffinity() with a prompt, chooseAction()) is asked before any effect applies.
  • Exceptions by ruling, where the rest of a "then" resolves anyway: Mark of Shame, Soul Beyond Reproach, Test of Courage, Tranquil Philosopher, Warriors of the Wind and Yogo Hiroue (one sequential()); Ichigo-kun and Aranat (afterwards()).
  • A step's context keeps earlier targets: context.target is still the card chosen in the first step.

If, if able, otherwise

  • "If X, do A. Otherwise, do B." is .if((context) => X).a().otherwise().b().
    • Without otherwise(), nothing happens when the condition fails; an ability whose only effect is that if() is then unusable.
    • Right after a card target, the branches belong to that target: they resolve on the chosen card after its own game actions, and only cards a branch can affect are selectable.
    • The branches stay on the ability when several card targets have no game actions, or when the target has game actions and the ability already has game actions of its own.
  • "Do A, if able. Otherwise, do B." is .ifAble().a().otherwise().b() (otherwise() required): A if it can resolve, else B. The branches always stay on the ability, so their game actions name their targets.

Cancelling and limits

If the effects of an ability are canceled, the ability is still considered to have been used, and any costs have still been paid.
Cancel

Costs stay paid and limits count the use when the effects are cancelled.

  • limit() is "Limit X per …", counted per copy. The default for an action or triggered ability (forced ones too) is once per round; "(Unlimited.)" is limit(unlimited()).
  • max() is "Max X per …", counted per player across all copies with that title.

Chat text

A resolved ability writes a chat line such as player1 plays Assassination, losing 3 honor to discard Doji Whisperer. The engine writes everything up to "to" (player, "plays" for an event or "uses" otherwise, card, costs). The rest comes from the ability:

  • By default it joins the game actions' own texts ("bow Doji Whisperer and draw 1 card"); often enough.
  • chatText('format') replaces it. {0} is the target (or the ring, or else the source); for anything more use the template form.
  • chatText((context) => msg`…`) (most cards) is a template that formats cards, players and rings; context.chatTarget() gives what {0} would.
  • Per choice: each select choice { action, chatText } has its own line; the ability then has no chatText().
  • A step (after then() or afterwards()) has no chatText(); its whole line, if any, comes from message((context) => msg`…`).

Pass game objects and keywords as values so the chat can format them:

  • Cards, players and rings go into a msg template or {N} arguments; in a plain string (`… ${card.name}`) they lose their formatting.
  • Military, political, element and clan names become icons only as separate values: msg`+2${'military'}`, not '+2 military'.
// wrong: the owner's name ends up as plain text
.chatText((context) => `return ${context.target.name} to ${context.target.owner.name}'s conflict deck`)
// right, as Field Tactician writes it: a msg template keeps the card and the player
.chatText((context) => msg`return ${context.chatTarget()} to ${context.target.owner}'s conflict deck`);

Conventions: a game message starts with the acting player, is in the present tense and has no final punctuation. Prompt titles say "Choose a <card type>" where possible. Changing an existing chat line needs approval.

Examples of more complex cards

"If you do": Ujiaki's Offer

// Ujiaki's Offer: Action: During a [conflict-political] conflict, choose a participating character with printed cost
// equal to or lower than that of another participating character you control - place 1 fate on the chosen character.
// If you do, bow it, move it home, and dishonor it.
this.action('Place a fate on a participating character, bow it, move it home, and dishonor it')
    .condition((context) => context.game.isDuringConflict(ConflictType.Political))
    .target({
        cardType: CardType.Character,
        cardCondition: (card, context) => card.isParticipating() && context.player.charactersInPlay.some((myCard) => (
            myCard !== card && myCard.isParticipating() && card.costAtMost(myCard.getCost())))
    }, placeFate())
    .chatText('place a fate on {0} then bow, dishonor, and move them home')
    .then()
    .bow((context) => ({ target: context.target }))
    .dishonor((context) => ({ target: context.target }))
    .sendHome((context) => ({ target: context.target }));

The fate is the target's own action; the rest is a then() step, so it only happens when the fate was placed. The step reads the chosen character as context.target.

A duel: Doji Reiha

// Doji Reiha: Conflict Action: Initiate a [conflict-political] duel against a character your opponent controls of
// their choice - resolve the duel. Honor each contestant character (in this duel). Then, the controller of the winner
// may choose to move each contestant home.
this.conflictAction('Initiate a duel that honors participants and move loser home')
    .initiateDuel(() => ({
        type: DuelType.Political,
        opponentChoosesDuelTarget: true,
        gameAction: (duel) => sequential([
            honor({ target: duel.participants }),
            chooseAction({
                player: duel.winnerController,
                choices: {
                    'Move all duel participants home': {
                        action: sendHome({
                            target: duel.participants
                        }),
                        message: (_context, _target, chooser) =>
                            msg`${chooser} chooses to move ${duel.participants.filter((card) => card.isParticipating())} home`
                    },
                    'Do nothing': { … }
                }
            })
        ]),
        onTie: (duel) => honor({ target: duel.participants })
    }));

gameAction resolves after a duel with a winner, onTie after a tie. "Then, … may choose" is made during resolution, so it is a chooseAction for the winner's controller, each choice with its own message.

If able, otherwise: Calling in Favors

// Calling in Favors: Action: Dishonor a (friendly) character. Choose an opponent's attachment – take control of
// that attachment and attach it to that character, if able. Otherwise, discard the attachment.
this.action('Take control of an attachment')
    .cost(costs.dishonor())
    .target({
        cardType: CardType.Attachment,
        controller: Players.Opponent
    })
    .ifAble()
    .attach((context) => ({
        target: context.costs.dishonor,
        attachment: context.target,
        takeControl: true
    }))
    .otherwise()
    .discardFromPlay((context) => ({ target: context.target }));

The dishonored character is a cost, recorded in context.costs.dishonor. If attaching is illegal (e.g. "… character only"), the attachment is discarded.

A choice before the dash: Hero of Three Trees

// Hero of Three Trees: Action: During a conflict in which this character is participating, if you have fewer cards
// in your hand than your opponent, select one - either gain 1 honor, or the attacked province gets -1 strength until
// the end of the conflict (to a minimum of 0).
this.action('Gain 1 honor or reduce the attacked province strength')
    .condition((context) => context.source.isParticipating())
    .ifCondition((context) => !!context.player.opponent && context.player.hand.length < context.player.opponent.hand.length)
    .select({
        'Gain 1 honor': {
            action: gainHonor(),
            chatText: 'gain 1 honor'
        },
        'Lower attacked province\'s strength by 1': {
            action: selectAttackedProvince({ … }),
            chatText: 'reduce the strength of an attacked province by 1'
        }
    });

"Select one" before the dash is a select(), each choice with its chat line. The card says "Action: During a conflict …", not "Conflict Action:", so it is an action() with the condition written out. "If you have fewer cards …" is a triggering condition: ifCondition(). context.player.opponent is checked because a solo game has none.

A granted ability: Kagi-Nawa

// Kagi-Nawa: If attached character has the Shinobi trait, it gains: “Conflict Action: Choose a character with
// printed cost 2 or lower - move that character to this conflict.”
this.whileAttached({
    match: (card) => card.hasTrait(Trait.Shinobi),
    effect: gainAbility.conflictAction('Move a character to the conflict', (ability) => ability
        .target({
            cardType: CardType.Character,
            controller: Players.Any,
            activePromptTitle: 'Choose a character with printed cost 2 or lower to move in',
            cardCondition: (card) => card.costAtMost(2)
        }, moveToConflict())
        .chatText('hook {0} and drag them into the conflict'))
});

Inside the granted ability, context.source is the character that gained it, not the attachment.

Testing a card

Every card gets a spec in test/server/cards/, mirroring the card's folder: test/server/cards/01-Core/Assassination.spec.js. A minimal one:

describe('Assassination', function () {
    integration(function () {
        beforeEach(function () {
            this.setupTest({
                phase: 'conflict',
                player1: {
                    honor: 10,
                    inPlay: ['doji-challenger'],
                    hand: ['assassination']
                },
                player2: {
                    inPlay: ['doji-whisperer']
                }
            });
            this.whisperer = this.player2.findCardByName('doji-whisperer');
            this.noMoreActions();
            this.initiateConflict({ attackers: ['doji-challenger'], defenders: ['doji-whisperer'] });
            this.player2.pass();
        });

        it('discards a character with printed cost 2 or lower', function () {
            this.player1.clickCard('assassination');
            expect(this.player1).toBeAbleToSelect(this.whisperer);
            this.player1.clickCard(this.whisperer);
            expect(this.whisperer.location).toBe('dynasty discard pile');
            expect(this.player1.honor).toBe(7);
            expect(this.getChatLogs(3)).toContain('player1 plays Assassination, losing 3 honor to discard Doji Whisperer');
        });
    });
});

gameModeA GameMode (default Stronghold); Emerald turns on its rules, e.g. one copy of an attachment per character.

Driving the game

  • this.player1.clickCard(card), clickPrompt('Text'), clickRing('air'), clickMenu(card, 'Text'), pass(), passConflict(), playAttachment(attachment, target), playCharacterFromHand(card, fate), placeCardInProvince(card, location), moveCard(card, location).
  • this.noMoreActions() passes both players' action windows; this.initiateConflict({ type, ring, province, attackers, defenders }) declares a conflict; this.flow.finishConflictPhase() and this.advancePhases(phase) move on.
  • Finding cards: findCardByName(id, location?), filterCardsByName(id).
  • Matchers: toHavePrompt(title), toHavePromptButton(text), toHaveDisabledPromptButton(text), toBeAbleToSelect(card), toBeAbleToSelectRing(element).
  • Chat: this.getChatLogs(n) returns the last n lines.

Rules the specs follow:

  • A "search the top X cards" card is tested with more than X cards in the deck, checking the rest stays untouched.
  • An engine bug (not one card's) gets its regression spec in test/server/integration/.
  • A select() before the dash always prompts (with "Pay costs first" unless a cost depends on a target, and "Cancel"), even with one legal choice, unless the opponent chooses. Click the choice (clickPrompt('Move into conflict')) before checking anything.
  • Any spec fails when a chat line contains choose a target for, the fallback text of selectCard and cardMenu: such an ability needs a chatText.
  • A spec should fail without the fix it tests. Run a subset with npm run jasmine -- <spec paths>.

Checks you don't write

A condition() or cardCondition that repeats an engine check is noise, and on province actions it can be wrong.

Already checkedSo don't addKeep a check when
conflictAction() requires a conflict and, on a character, its participation.isDuringConflict(), context.source.isParticipating()The text adds more, such as a ring or a player state.
A province's action() works only during a conflict at that province (conflictProvinceCondition changes which; canTriggerOutsideConflict() turns the check off).isConflictProvince() or isDuringConflict() in its conditionNever for the province itself: Keeper of Secret Names resolves a province's action ignoring Blocker.WrongProvince, and a repeated check would stop it.
initiateDuel() with requiresConflict (the default) needs a participating challenger and duel target, unless it sets its own challengerCondition or targetCondition.isDuringConflict(), the source's isParticipating()The duel needs a conflict type: isDuringConflict(ConflictType.Military); or it sets its own challengerCondition/targetCondition, which replace the participation check.
A target whose cardCondition needs isParticipating(), isAttacking() or isDefending(): no card passes without a conflict.isDuringConflict() on the abilityIt checks the conflict type, guards game.currentConflict, or the ability has no target to filter (so nothing else stops paying costs outside a conflict).
sendHome only affects participating characters, moveToConflict only characters at home during a conflict.isParticipating() / !isParticipating() in that target's cardCondition, isDuringConflict() on the abilityThe target has no game action of its own and a later target's action reads it (context.targets.character): its condition is the only filter.

Not redundant: isDuringConflict() in a when() (nothing else checks triggers), and condition: (context) => context.source.isConflictProvince() on a province's persistentEffect for "while this province is being attacked" (persistent effects have no province check).

Common mistakes

  • Changing state directly (card.bowed = true, player.moveCard(…), context.target = …): it skips events, so reactions, interrupts, restrictions and chat never see it. Use game actions.
  • A handler() where a game action exists. A handler is the last resort: it raises no event, so the engine can't tell whether it would change anything; it has no default chat text; no step can follow it.
  • .gameAction(x(…)) where a shortcut exists: write .x(…).
  • A choice after the dash written as a target, or vice versa (timing).
  • "Then" as afterwards(): "then" is then(), unless a ruling lets the rest resolve anyway.
  • Repeating a default: { target: context.source } on a card game action outside a target (they default to the source), or player: Players.Self on a target.
  • Reading context.costs in a condition without handling undefined (see the context).
  • The card's own state (this.parent, this.fate, …) in a callback instead of context.source: wrong for copies and gained abilities. this.game and helper methods of the card's class (this.countBushi(context)) are fine.
  • A conditional() for "Select one –": it picks a branch without asking. A player's choice is a select() (before the dash) or chooseAction (after it).
  • Repeating engine checks (checks you don't write).
