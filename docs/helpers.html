Jigoku Card builder reference

Card helpers and queries

Shared helpers for families of cards, and the card, player and game queries abilities use most.

Shared card helpers

Some cards share most of their implementation: the province attachments, the mantras, the cards that search for an attachment, the cards with a "claimed ring" symbol. The shared parts live in the modules directly in server/game/cards/ (not in a set folder). Import them with '../name.js' from a set folder such as 01-Core/, and with '../../name.js' from a clan folder such as 20-Core2/Crab/.

Before you write a helper for a new card, check this list. If two or more cards need the same code, put it in a module here; code that only one card uses stays in that card's file.

Base classes

Extend these instead of DrawCard when the card is one of these kinds. They change where the card can be played and attached; the card's abilities are still declared in setupCardAbilities().

class X extends BattlefieldAttachment Base class #

A ProvinceAttachment with "Limit 1 Battlefield attachment per province." Its setupCardAbilities() adds attachmentConditions({ limitTrait: { battlefield: 1 } }).

  • When your card declares its own abilities, call super.setupCardAbilities() first, or the Battlefield limit is lost.
  • When a second Battlefield attachment is attached to the same province, the earlier one is discarded as no longer legal.
  • Everything else comes from ProvinceAttachment: by default it can only be played on an unbroken province. Override unbrokenOnly() to return false for "Attach to a province." (Field of Ruin, Declaration of Dominion).
// Total Warfare: Attach to an unbroken province. Limit 1 Battlefield attachment per province.
// Forced Reaction: After a player loses a conflict at attached province - that player must sacrifice a participating character.
export default class TotalWarfare extends BattlefieldAttachment {
    static id = 'total-warfare';

    public setupCardAbilities() {
        super.setupCardAbilities();
        this.forcedReaction('Loser sacrifices a character')
            .when({
                afterConflict: (event, context) =>
                    event.conflict.loser && context.source.parentProvince?.isConflictProvince()
            })
            …
    }
}

class X extends ProvinceAttachment Base class #

An attachment that is played on and attached to a province instead of a character. canPlayOn and canAttach accept only a card of type province, and only while the card itself is an attachment.

OverrideReturnsDefaultMeaning
unbrokenOnly()booleantrueOnly an unbroken province can be chosen. Return false for "Attach to a province."
controllerProvinceOnly()booleanfalseOnly a province with the same controller as the attachment can be chosen: "Attach to a province you control."
  • Both overrides are protected methods, not constructor options.
  • ProvinceAttachment replaces canAttach, so the restrictions of attachmentConditions that canAttach checks for character attachments (myControl, opponentControlOnly, unique, faction, trait, cardCondition) have no effect here. Use the two overrides. Trait limits (limitTrait) and limit still apply.
  • canAttach is checked again while attached: with unbrokenOnly() the attachment is no longer legal, and is discarded, once its province is broken.
  • The attachment reaches its province with context.source.parent or parentProvince.
// Inventive Buttressing: Attach to an unbroken province you control.
// Attached province gets +3 strength during [conflict-military] conflicts.
class InventiveButtressing extends ProvinceAttachment {
    static id = 'inventive-buttressing';

    setupCardAbilities() {
        this.persistentEffect({
            condition: () => this.game.isDuringConflict(ConflictType.Military),
            targetLocation: Location.Provinces,
            match: (card, context) => card === context?.source.parent,
            effect: modifyProvinceStrength(3)
        });
    }

    protected controllerProvinceOnly(): boolean {
        return true;
    }
}

Used by Educated Heimin, Inventive Buttressing, Untainted, Ward of Earthen Thorns (6 card files)

class X extends RingAttachment Base class #

An attachment played on and attached to a ring: "Attach to a ring." canPlayOn and canAttach accept only a ring, and mustAttachToRing() returns true, all while the card is an attachment.

  • The ring is this.parent (a Ring, not a card); check it with parent instanceof Ring or parent?.isRing() before using ring methods.
  • The checks look at the card's current type, so a card that only becomes an attachment through an effect (Crafty Tsukumogami uses changeType(CardType.Attachment)) behaves as a ring attachment only while it is one.
// Greater Understanding: Attach to a ring.
// Reaction: After fate is placed on attached ring - resolve that ring's effect as if you were the attacking player.
class GreaterUnderstanding extends RingAttachment {
    static id = 'greater-understanding';

    setupCardAbilities() {
        this.reaction('Resolve the attached ring\'s effect')
            .when({
                onMoveFate: (event) => event.recipient === this.parent,
                onPlaceFateOnUnclaimedRings: () => this.parent instanceof Ring && this.parent.isUnclaimed()
            })
            .resolveRingEffect((context) => ({ target: context.source.parent ?? [] }));
    }
}

abstract class TokenCard extends DrawCard Base class #

A facedown card that is in play as a token ("put the top card of your dynasty deck into play facedown as a 1 military … character"). The token class holds the token's printed data; the real card is kept in facedownCard. You don't create tokens yourself: the game actions tokenFromTopCard and createToken take the token class and make one.

Parameter / memberTypeDefaultMeaning
facedownCardDrawCardrequiredThe card that became the token. Constructor parameter and public field.
cardDataCardDatarequiredThe token's printed data: id, name, type, clan, side, military, political, glory, cost, traits, is_unique, text, and for attachments military_bonus, political_bonus, attachment_allow_duplicates.
facedownDestination(destination?)stringLocation.DynastyDiscardPileProtected. Where facedownCard goes when the token leaves play.
  • When the token leaves play, the facedown card moves to facedownDestination(destination) and the token object is removed from its pile and from game.allCards: the token is gone, not discarded.
  • The token is owned by the facedown card's owner.
  • In the client the token shows as a token; only its controller sees which card is facedown under it.
// Ashigaru Encampment: Action: Put the top card of your dynasty deck into play facedown (at home)
// as a 1 [conflict-military], 0 [conflict-political], 1 glory [clan-lion] character with the Peasant trait.
this.action('Recruit a fresh Ashigaru')
    .tokenFromTopCard({
        deck: DeckType.Dynasty,
        token: AshigaruRecruit,
        gameAction: (token) => putIntoPlay({ target: token })
    })
    .chatText(() => msg`recruit ${recruitInChat}`);

Used by AshigaruRecruit, Soldier, SpiritOfTheRiver, UnleashedHound

Trackers

Some card text depends on what happened earlier: "a character that entered play during this conflict", "a character that has won a duel during this conflict". A tracker listens to game events and remembers. Create it once in setupCardAbilities() and keep it in a local constant; each copy of the card then has its own tracker.

new CharactersEnteredThisConflict(game) Tracker #

Remembers each character that entered play (onCharacterEntersPlay) since the current conflict started. has(card) answers "did this character enter play during this conflict?".

MemberTypeDefaultMeaning
gameGamerequiredConstructor parameter: this.game.
has(card)(card: BaseCard) => booleanWhether the card entered play since the last onConflictStarted.
  • The list is cleared when a conflict starts, not when it ends. Between two conflicts it still holds the characters from the last one, so use it in abilities that only work during a conflict.
// Zealous Exorcist: Conflict Action: Choose a character that entered play during this conflict - remove that character from the game.
const charactersEntered = new CharactersEnteredThisConflict(this.game);
this.conflictAction('Remove a character from play')
    .target({
        cardType: CardType.Character,
        cardCondition: (card) => charactersEntered.has(card)
    }, removeFromGame());

Used by The Maiden's Icy Grasp, Zealous Exorcist

new ConflictsDeclaredThisRound(game) Tracker #

Records the province each conflict was declared against this round, for "the attacked province has had a previous conflict declared against it this round" and "for each conflict declared against this province this round".

MemberTypeDefaultMeaning
gameGamerequiredConstructor parameter.
countAgainst(province)(province: ProvinceCard | undefined) => numberThe number of conflicts declared against the province this round, the current one included. 0 for undefined.
wasAttackedBefore(province, conflict)(province: ProvinceCard, conflict: Conflict | null) => booleanWhether a conflict other than conflict was declared against the province this round.
  • A declaration is recorded when the reaction window of onConflictDeclared opens, so a reaction to the declaration already counts the current conflict.
  • The record is per province card and location: a province that moves counts as a different one. It only looks at the province the conflict was declared against (declaredProvince), not at provinces added later.
  • Cleared at the end of the round.
// Song of the Empty City: Reaction: After your opponent declares a conflict against this holding's province -
// gain 1 honor for each conflict declared against this province this round. (Unlimited.)
const declaredConflicts = new ConflictsDeclaredThisRound(this.game);
this.reaction('Gain honor')
    .when({
        onConflictDeclared: (event, context) => event.conflict.declaredProvince === context.player.getProvinceCardInProvince(context.source.location)
    })
    .gainHonor((context) => ({
        amount: declaredConflicts.countAgainst(context.player.getProvinceCardInProvince(context.source.location))
    }))
    .limit(unlimited());

Used by Song of the Empty City, Vengeful Kami

DuelsThisConflict.winners(game, options?) Tracker #

Remembers characters from each duel resolved during the current conflict. The static factories pick which ones; has(card) answers the question.

MemberTypeDefaultMeaning
DuelsThisConflict.winners(game, options?)factory"has won a duel during this conflict": each duel's winner.

new LimitedPlaysFromOutOfPlay<this>(card, options) Tracker #

Counts the plays a card allows "as if it were in your hand", for "You cannot play more than 3 cards per round this way." It adds a persistent effect to card that counts each matching play, writes the chat line and runs afterPlay. It does not make anything playable: the card's own persistent effect does that and must check available.

PropertyTypeDefaultMeaning
cardT extends DrawCardrequiredConstructor parameter: the card (this).
maxnumberrequiredPlays allowed per round.
active(context) => booleanrequiredWhile the card lets its player play these cards, for example "during political conflicts in which this character is participating".
allows(event, context) => booleanrequiredWhether an onCardPlayed event is a play this card allows, for example event.originalLocation === Location.ConflictDeck.
descriptionstringrequiredChat text after the player's name: "plays a card from their conflict deck".
afterPlay(event, context) => voidnoneRuns after a counted play, for example to remove the played card from the game.
availablegetter, booleanWhether the card still allows a play this round.
  • A play counts only if it was made by the card's player, active and allows are true, and no other source already counted it (plays credited to another "play from out of play" source are skipped).
  • The count goes back to 0 at the end of the round and when the card enters play.
  • Chat: "{player} {description} due to the ability of {card} (N uses remaining)".
// Master Tactician: During conflicts in which this character is participating, if there is a Battlefield in play, you may look at
// and play the top card of your conflict deck as if it were in your hand. You cannot play more than 3 cards per round this way.
const plays = new LimitedPlaysFromOutOfPlay<this>(this, {
    max: 3,
    active: (context) => context.source.isParticipating() && context.game.isTraitInPlay('battlefield'),
    allows: (event) => event.originalLocation === Location.ConflictDeck && !!event.originallyOnTopOfConflictDeck,
    description: 'plays a card from their conflict deck'
});

this.persistentEffect({
    condition: (context) =>
        context.game.isTraitInPlay('battlefield') &&
        context.source.isParticipating() &&
        plays.available,
    …
});

Ability factories

These build a whole ability, a game action or the properties for a builder call, for card text that several cards share word for word.

attachmentSearch({ controller, maxCost? }) Game action #

"Search the top 5 cards of your conflict deck for an attachment and put it into play attached to a character. Shuffle." Returns a sequential action: a card menu of the top 5 cards, then a character choice for the chosen attachment, then a shuffle of the player's conflict deck.

PropertyTypeDefaultMeaning
controllerPlayersrequiredWhose characters may receive the attachment: Players.Self for "a character you control", Players.Any for "a character".
maxCostnumberno limitHighest printed cost of the attachment.
  • Only attachments that can be attached to at least one eligible character can be picked. The menu always has "Take nothing", so the ability can be used with no attachment in the top 5.
  • The deck is shuffled in every case, also after "Take nothing".
  • Chat: "{player} chooses to attach {attachment} to {character}", or "{player} takes nothing".
// Excellence, Attained: Reaction: After a conflict is declared against this province - search the top 5 cards of your conflict deck
// for an attachment with printed cost 1 or less and put it into play attached to a character. Shuffle.
this.reaction('Search for an attachment')
    .when({
        onConflictDeclared: (event, context) => event.conflict.declaredProvince === context.source && context.player.conflictDeck.length > 0
    })
    .gameAction(attachmentSearch({ controller: Players.Any, maxCost: 1 }))
    .chatText('search the top 5 cards of their conflict deck for an attachment and put it into play');

Used by Illustrious Forge, Excellence, Attained

moveCardInProvinceAction(source) Ability #

Declares the action "choose a card in or attached to a province - move that card to another unbroken non-stronghold province controlled by the same player" on source and returns the builder, so you can add costs and steps.

ParameterTypeDefaultMeaning
sourceDrawCardrequiredThe card the action belongs to (this).
  • First target cardInProvince: an attachment, character, event or holding in a province (not a province or stronghold), or an attachment attached to a province. Second target province: unbroken, not the stronghold province, same controller as the card (for an attachment, as its province), and a different location.
  • An attachment is re-attached to the new province; any other card is moved there.
  • Chat: "move {card} to {province}", with "a facedown card" or the location name in place of facedown cards.
// Stone Breaker: Action: Sacrifice this holding and choose a card in or attached to a province - move that card to another unbroken
// non-stronghold province controlled by the same player. Refill this province face up.
moveCardInProvinceAction(this)
    .cost(costs.sacrificeSelf())
    .refillFaceup((context) => ({ location: context.cardStateWhenInitiated?.location ?? [] }));

nameCardType(), revealCount(context, trait), takeUpToTwoOfNamedType(context, trait) Cost and deck search #

The parts of "Name a card type. Reveal the top 3 cards of your conflict deck (top 4 cards instead if you control a [Trait] character) – add up to 2 revealed cards of that type to your hand and discard the rest."

nameCardType()Cost<{ namedCardType: CardType }>A free cost that asks the player to pick attachment, character or event, stored as context.costs.namedCardType.

randomHandCards(player, amount), chooseCardToDiscard(cards) Helper and game action #

"Reveal X random cards from their hand … Choose and discard one of those cards." randomHandCards picks the cards; chooseCardToDiscard is a card menu in which the ability's player picks one of them to discard.

ParameterTypeDefaultMeaning
playerPlayer | undefinedrequiredWhose hand. undefined (no opponent) gives no cards.
amountnumberrequiredHow many cards; fewer if the hand is smaller.
cardsDrawCard[]requiredFor chooseCardToDiscard: the cards to choose from.
  • The random cards are sorted by name, so their order shows nothing about the shuffle.
  • Call randomHandCards once inside a multiple((context) => …) or sequential((context) => …) factory and pass the same array to the reveal and to chooseCardToDiscard, so both see the same cards.
  • chooseCardToDiscard sets targets: true. Chat: "{player} chooses {card} to be discarded".
// Hida Marauder: Reaction: After this character wins a conflict - your opponent reveals X random cards from their hand,
// where X is the number of characters on your side. Choose and discard one of those cards.
.gameAction(multiple((context) => {
    const count = context.game.currentConflict?.getCharacters(context.player).length ?? 0;
    const cards = context.player.opponent && count > 0 ? randomHandCards(context.player.opponent, count) : [context.source];
    return [
        reveal({ target: cards, chatMessage: true, player: context.player.opponent }),
        chooseCardToDiscard(cards)
    ];
}))

Used by Tranquil Overlook Dojo, Hida Marauder, Isawa Haruyo, Loyal Attendant

"Reveal the top card of your conflict deck. Until the end of the phase, you may play that card as if it were in your hand." Returns the properties for .playerLastingEffect(…): the top card is shown and can be played from the deck.

ParameterTypeDefaultMeaning

Queries

Conditions and callbacks ask the game about its state: is this character participating, is the player more honorable, is the ring claimed. These are the methods card abilities call most often, counted over all card files and grouped by the object they are called on. You reach the objects from the context: context.source (the card), context.player and context.player.opponent, context.game, context.game.currentConflict, and in triggers event.card, event.conflict, event.ring.

Queries only read. To change the game state, use a game action, so that interrupts, reactions and restrictions see the change.
