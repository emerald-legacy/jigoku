Jigoku Card builder reference

Effects

Every effect a card can apply, what it applies to, its parameters and how it stacks.

How effects work

An effect changes how the game treats a card, a player, a ring, a conflict or a duel for as long as it applies: +2 military skill, "cannot be bowed", an extra conflict. Effects don't happen once like game actions; they hold while their condition and duration hold, and the game recalculates them after every change. The factories are exported from server/game/effects.ts.

Where an effect goes

Card textUse
A constant ability: "Each participating character you control gets +1 military."this.persistentEffect({ match, targetController, condition, effect })
"Attached character gets +2 military."this.whileAttached({ effect })
"… until the end of the conflict" in an abilityThe game actions cardLastingEffect, playerLastingEffect, ringLastingEffect, conflictLastingEffect, duelLastingEffect (on the game actions page)
"This turn / until the end of the phase" for the next card playedplayerLastingEffect with the effect, e.g. reduceNextPlayedCardCost

Each entry below says what an effect applies to. Use a card effect where a card is targeted (persistentEffect with match, whileAttached, cardLastingEffect), a player effect where a player is (persistentEffect with targetController, playerLastingEffect), and so on.

Fixed and computed values

Some effects take a value or a function of the game state: modifyMilitarySkill(2) or modifyMilitarySkill((card, context) => card.attachments.length). A function is recalculated whenever the game state changes. The entries say which effects take one.

Several effects at once

  • Pass a list to apply several effects with one ability: effect: [modifyMilitarySkill(1), addTrait('bushi')].
  • Modifiers add up; for effects that set a value (setMilitarySkill, …), the most recent one wins. The entries note the exceptions.
  • A blanked card loses its printed abilities, and with them its persistent effects; effects other cards apply to it stay.

Reference

Traits, keywords, factions and card type

Card effects that change what a card is: its traits, keywords, clan, card type or whole text box. Put them on a card with persistentEffect (a match picks the cards), whileAttached or cardLastingEffect.

addFaction(faction) Card effect #

The card gains a clan symbol: "Attached character gains the [clan-crane] clan symbol."

ParameterTypeDefaultMeaning
factionFactionrequiredOne of 'crab', 'crane', 'dragon', 'lion', 'phoenix', 'scorpion', 'unicorn', 'neutral', 'shadowlands'. A fixed value.
  • getFactions() is the printed faction plus every added one, minus every faction removed by loseFaction. loseFaction wins over addFaction for the same faction.
  • isFaction('neutral') is true only while neutral is the card's only faction, so a neutral character that gains a clan stops being neutral.
  • On a copy (copyCard) the copied card's printed faction replaces the card's own; added factions still apply.
  • Blanking does not remove the printed faction.
// Seal of the Crane: Attached character gains the [clan-crane] clan symbol and the Duelist trait.
this.whileAttached({
    effect: [
        addFaction('crane'),
        addTrait('duelist')
    ]
});

Used by Seal of the Crane, Seal of the Scorpion, Seal of the Crab, Seal of the Phoenix

addKeyword(keyword) Card effect #

The card gains a keyword: "Attached character gains pride."

ParameterTypeDefaultMeaning
keywordstringrequiredThe keyword in lower case: 'pride', 'covert', 'sincerity', 'ancestral', … A fixed value.
  • hasKeyword(k) counts the addKeyword effects for k and the loseKeyword effects for it, and is true while there are more added than lost. Two copies of the keyword survive one loseKeyword.
  • Printed keywords are applied the same way: the engine gives every card an addKeyword persistent effect per printed keyword. Blanking the card removes those, not keywords other cards give it.
  • hasKeyword lower-cases the name it is asked about, not the stored value, so pass the keyword in lower case.
  • While the card has loseGainedAbilities, only keywords from its own effects count. loseAllNonKeywordAbilities keeps keyword effects.
// Magnificent Kimono: Attached character gains pride. (…)
this.whileAttached({
    effect: addKeyword('pride')
});

Used by Magnificent Kimono, Asahina Storyteller, Tattooed Wanderer, Cherished Family Servant

addTrait(trait) Card effect #

The card gains a trait: "Attached character gains Tattooed."

ParameterTypeDefaultMeaning
traitstringrequiredThe trait in lower case ('bushi', 'tattooed'). A fixed value.
  • getTraits() is the printed traits, plus every added trait, minus every trait removed by loseTrait. Removal is applied last, so loseTrait wins.
  • hasTrait lower-cases the trait it is asked about, not the stored value: pass lower case.
  • blank(true) removes printed traits; added traits stay. On a copy the copied card's traits replace the printed ones.
// Hawk Tattoo: Attach to a character you control. Attached character gains Tattooed. …
this.whileAttached({
    effect: addTrait('tattooed')
});

Used by Favored Mount, Seal of the Crane, Hawk Tattoo, Voice of the Ancestors

blank(blankTraits?) Card effect #

The card treats its printed text box as blank: "Attached character loses all printed abilities."

ParameterTypeDefaultMeaning
blankTraitsbooleanfalseAlso remove the card's printed traits.
  • Printed actions and triggered abilities can't be used (their requirement check returns Blocker.Blanked); the card's own persistent effects stop, and with them its printed keywords.
  • Abilities it gained from other cards (gainAbility) keep working, and effects other cards put on it stay. Use loseGainedAbilities for gained ones.
  • A blank card ignores its "No attachments except …" restriction: any attachment is allowed.
  • One blank is enough; any copy with blankTraits true removes the traits. copyCard and copyProvince also make the card count as blank (isBlank()).
  • A province also counts as blank while it is broken or dishonored.
// Cloud the Mind: Play only if you control a Shugenja character. Attached character loses all printed abilities.
this.whileAttached({
    effect: blank()
});

Used by Cloud the Mind, Cautious Scout, A Fate Worse Than Death, Voice of the Ancestors

changeType(type) Card effect #

The card's type becomes type: "turn it into a character", "attach this card … as an attachment".

ParameterTypeDefaultMeaning
typeCardTyperequiredThe new type, e.g. CardType.Character.
  • The most recent changeType wins; printedType is unchanged.
  • Only the type changes. A former attachment that becomes a character has no skills of its own; give it some with setBaseMilitarySkill and friends, as Togashi Hoshi does.
  • The effect usually needs Duration.Custom or canChangeZoneOnce, so it survives the card moving.
// Togashi Hoshi: Action: Detach an attachment from a character you control and turn it into a character. …
this.action('Turn attachment into character')
    .selectCard({
        cardType: CardType.Attachment,
        cardCondition: (card, context) => card.parentCharacter?.controller === context.player,
        subActionProperties: (card) => ({
            target: card,
            effect: [changeType(CardType.Character)].concat(…)
        }),
        gameAction: multiple([
            detach(),
            cardLastingEffect({ duration: Duration.Custom })
        ])
    });

Used by Togashi Hoshi, Voice of the Ancestors, Promising Youth, Loyal Warhound

copyCard(character) / copyProvince(province) Card effect #

The card "becomes a copy of" another character or province: it takes the other card's name, printed traits, printed faction and abilities.

ParameterTypeDefaultMeaning
characterDrawCardrequiredcopyCard: the card to copy. Also used for holdings (Floating Fortress).
provinceProvinceCardrequiredcopyProvince: the province to copy.
  • copyCard also copies the printed cost, printed skills and printed glory; copyProvince copies the printed strength and the province elements. Modifiers on the card still apply on top.
  • The copied abilities are read when copyCard(…) is called. Copied actions and triggered abilities get fresh limits; copied persistent effects only start if their location fits the card (play area for a character, provinces for a holding or province, or Location.Any).
  • The card's own printed abilities are blanked (isBlank() is true), except its own keyword reactions. Abilities and effects from other cards stay.
  • With several copy effects, the most recent one wins.
// Shosuro Actor: Action: During a conflict in which this character is participating, choose a non-unique
// character you do not control - this character becomes a copy of that character until the end of the conflict.
this.action('Choose a character to copy')
    .condition((context) => context.source.isParticipating())
    .target({
        player: Players.Self,
        cardType: CardType.Character,
        controller: Players.Opponent,
        cardCondition: (card) => !card.isUnique()
    }, cardLastingEffect((context) => ({
        target: context.source,
        effect: context.target ? copyCard(context.target) : []
    })))
    .chatText((context) => msg`become a copy of ${context.target}`);

Used by Shosuro Actor, Miyako's Undertaking, Floating Fortress, Illusionary Terrain (copyProvince)

Skills, glory and contribution

Effects on what a character adds to a conflict or a glory count. Plain skill modifiers (modifyMilitarySkill, setMilitarySkill, …) are in the second half of this page.

attachmentMilitarySkillModifier(value) / attachmentPoliticalSkillModifier(value) Card effect #

An attachment's skill bonus: "+X [conflict-military]" printed on an attachment, where X is computed.

ParameterTypeDefaultMeaning
valuenumber | (card, context) => numberrequiredThe bonus, fixed or recalculated for each target.
  • It adds up with all other skill modifiers, like modifyMilitarySkill. The difference is the label: rules that treat attachment bonuses specially read these two effect names (switchAttachmentSkillModifiers, Shore of the Ashen Flames, Bayushi Gensato, Mirumoto Rei).
  • The engine already creates one for every attachment with a printed numeric bonus. Use these only for a bonus printed as X.
  • A character with a dash in that skill keeps the dash.
// Born in War: Cavalry character only. X is equal to the number of unclaimed rings.
this.attachmentConditions({
    trait: 'cavalry'
});
this.whileAttached({
    effect: attachmentMilitarySkillModifier((_card, context) =>
        Object.values(context.game.rings).filter((ring) => ring.isUnclaimed()).length)
});

Used by Born in War, Kobo Ichi-Kai Jujutsu, Mirumoto Rei, A Plague of Yokai

calculatePrintedMilitarySkill(func) Card effect #

Computes a printed [conflict-military] skill of X: "X is equal to the number of cards in your opponent's hand."

ParameterTypeDefaultMeaning
func(card: DrawCard) => numberrequiredCalled with the character on every skill calculation; its result replaces the printed military skill.
  • Only military skill; there is no political version.
  • It replaces the printed value as the base, so all modifiers still apply on top. Effects that set the base skill (setBaseMilitarySkill, setBaseDash) override it.
  • Without the effect, a printed X counts as 0.
// Iron Crane Legion: … During conflicts in which you are the attacking or defending player,
// X is equal to the number of cards in your opponent's hand. (Otherwise, X is zero.)
this.persistentEffect({
    condition: (context) => context.game.isDuringConflict(),
    effect: calculatePrintedMilitarySkill((card) => card.controller.opponent?.hand.length ?? 0)
});

Used by Iron Crane Legion

canContributeGloryWhileBowed() Card effect #

"This character contributes its glory to glory counts even while bowed."

  • Only glory counts: a glory count (performGloryCount) sums getGloryCount(), where a bowed character adds its glory only with this effect. For conflict skill use canContributeWhileBowed.
// Miya Kogara: … This character contributes its glory to glory counts even while bowed.
this.persistentEffect({
    effect: canContributeGloryWhileBowed()
});

Used by Miya Kogara, The Empress' Legacy, Steward of Celestial Order

canContributeWhileBowed() Card effect #

"Bowed participating characters contribute their skill toward the resolution of the conflict."

  • Only lifts the "bowed characters don't count" rule. cannotContribute and a RestrictionType.ContributeSkillToConflictResolution restriction still stop the character.
// Nimble Noyan: … Dire - While this character is participating in a conflict, bowed participating
// characters contribute their skill toward the resolution of the conflict. …
this.dire({
    condition: (context) => context.source.isParticipating(),
    targetController: Players.Any,
    match: (card) => card.type === CardType.Character && card.isParticipating(),
    effect: canContributeWhileBowed()
});

Used by Nimble Noyan, Incessant Moto

cannotContribute(func) Conflict effect #

Some characters "do not count their skill toward the resolution of this conflict".

ParameterTypeDefaultMeaning
func(conflict, context) => (card: DrawCard) => booleanrequiredRecalculated for the current conflict on every state check; returns the test for the characters that don't count.
  • A conflict effect always applies to the current conflict and does nothing outside one; match is ignored. Use it in a persistentEffect with a condition, or in conflictLastingEffect.
  • With several effects, a character is left out if any of them matches it.
// Swift Magistrate: While this character is attacking, each other character that has 1 or more fate
// on it does not count its skill toward the resolution of this conflict.
this.persistentEffect({
    condition: (context) => context.source.isAttacking(),
    effect: cannotContribute((_conflict, context) => {
        return (card) => card.getFate() > 0 && card !== context.source;
    })
});

Used by Swift Magistrate, Stoic Magistrate, Haughty Magistrate, Humble Magistrate

changeConflictSkillFunction(func) Conflict effect #

"While resolving this conflict, characters count their glory instead of their skill": replaces what each counted character adds to its side.

ParameterTypeDefaultMeaning
func(card: DrawCard, conflict: Conflict) => numberrequiredWhat the character adds to its side's total.
  • Applies to both sides of the current conflict. The most recent one wins.
  • It bypasses changeContributionFunction: without this effect each character adds getContributionToConflict(type), which is where that effect is read.
  • A player's changeConflictSkillFunctionPlayer takes precedence for that player's characters.
  • Bowed characters, cannotContribute and contribution restrictions still leave characters out before the function is called.
// Sanpuku Seidō: … While resolving a conflict at this province, characters count their glory
// instead of their [conflict-military] skill and [conflict-political] skill.
this.persistentEffect({
    condition: (context) => context.source.isConflictProvince(),
    effect: changeConflictSkillFunction((card) => card.glory)
});

Used by Sanpuku Seidō, Massing at Twilight, Shiba Ryuu, River Crossing

changeConflictSkillFunctionPlayer(func) Player effect #

Like changeConflictSkillFunction, but only for characters the affected player controls: "attacking characters cannot have their skills increased by attachment cards".

ParameterTypeDefaultMeaning
func(card: DrawCard, conflict: Conflict) => numberrequiredWhat each of the player's counted characters adds.
  • It is read from the counted character's controller and wins over the conflict's changeConflictSkillFunction. With several on one player, the most recent wins.
  • Choose the player with targetController (Players.Self by default).
// Shore of the Ashen Flames: While resolving a conflict at this province, attacking characters
// cannot have their skills increased by attachment cards.
this.persistentEffect({
    condition: (context) => context.source.isConflictProvince(),
    targetController: Players.Opponent,
    effect: changeConflictSkillFunctionPlayer((card, conflict: Conflict) => {
        const exclusionFunction = (effect: EffectApplier) => { … };
        if(conflict.conflictType === ConflictType.Military) {
            return card.getMilitarySkillExcludingModifiers(exclusionFunction);
        }
        return card.getPoliticalSkillExcludingModifiers(exclusionFunction);
    })
});

Used by Shore of the Ashen Flames

changeContributionFunction(func) Card effect #

Changes what one character contributes to the conflict: "that character contributes its printed [conflict-military] skill".

ParameterTypeDefaultMeaning
func(card: DrawCard) => numberrequiredThe amount the character contributes.
  • The most recent one wins. It replaces getContributionToConflict(), which is ignored while a changeConflictSkillFunction or changeConflictSkillFunctionPlayer applies.
  • It does not make the character count; pair it with contributeToConflict for a character that isn't participating.
// Hiruma Yoshino: … Action: During a [conflict-military] conflict in which this character is participating,
// choose a character card in the attacked province - that character contributes its printed
// [conflict-military] skill towards your side during the resolution of this conflict.
this.action('Contribute printed military skill')
    .condition((context) => context.game.isDuringConflict(ConflictType.Military) && context.source.isParticipating())
    .target({
        cardType: CardType.Character,
        location: Location.Provinces,
        cardCondition: (card) => card.isInConflictProvince() && card.printedMilitarySkill > 0
    }, cardLastingEffect({
        targetLocation: Location.Provinces,
        effect: [
            contributeToConflict((_card, context) => context.player),
            changeContributionFunction((card) => card.printedMilitarySkill)
        ]
    }));

Used by Hiruma Yoshino

changePlayerGloryModifier(value) Player effect #

"This holding adds +3 to your side during each glory count."

ParameterTypeDefaultMeaning
valuenumber | (player, context) => numberrequiredThe amount added, fixed or recalculated.
  • All copies add up (Player.gloryModifier). The total is added to the player's glory count, with the claimed rings and the glory of ready characters.
// The Imperial Palace: Limit 1 per deck. This holding adds +3 to your side during each glory count.
this.persistentEffect({
    effect: changePlayerGloryModifier(3)
});

Used by The Imperial Palace, The Empress' Legacy, Whispers of the Lords of Death

changePlayerSkillModifier(value) Player effect #

"Add +3 to your skill during conflict resolution": changes the player's total, not a character's skill.

ParameterTypeDefaultMeaning
valuenumber | (player, context) => numberrequiredThe amount added to the player's side, fixed or recalculated.
  • All copies add up (Player.skillModifier), on top of the characters' skill and the imperial favor bonus.
  • Ignored while the player has setConflictTotalSkill.
// Daidōji Akikore: … Conflict Action: Initiate a [conflict-military] duel against a character your opponent
// controls of their choice - resolve the duel. If this character wins the duel, add +3 to your skill during
// conflict resolution. …
this.conflictAction('Military duel to add skill')
    .initiateDuel((context) => ({
        type: DuelType.Military,
        opponentChoosesDuelTarget: true,
        gameAction: (duel) =>
            conditional({
                condition: duel.winningPlayer === context.player,
                trueGameAction: playerLastingEffect({
                    target: duel.winningPlayer,
                    effect: changePlayerSkillModifier(3)
                })
            })
    }));

Used by Daidōji Akikore, Disguised Protector, Marvelous Beings, Cantor of Gales

contributeToConflict(player) Card effect #

A character that isn't participating "contributes its skill to your side".

ParameterTypeDefaultMeaning
playerPlayer | (card, context) => PlayerrequiredThe side it counts for. Cards pass a function, usually (_card, context) => context.player.
  • Only characters in the play area or in a province count. The character does not become a participant.
  • The usual rules still apply: a bowed character adds nothing (unless canContributeWhileBowed), nor does one excluded by cannotContribute or a contribution restriction.
  • Does nothing while that side's total is set by setConflictTotalSkill.
// Kaito Kosori: During each [element-air] conflict, if you control at least 1 participating character and if
// this character is in your home area and ready, it contributes its skill to your side.
this.persistentEffect({
    condition: (context) => {
        const symbol = this.getCurrentElementSymbol(elementKey);
        return context.player.cardsInPlay.some((card) => card.isParticipating()) &&
            this.game.isDuringConflict(symbol) &&
            !context.source.isParticipating() && !context.source.bowed;
    },
    effect: contributeToConflict((_card, context) => context.player)
});

Used by Kaito Kosori, Hiruma Yoshino

Attachment restrictions

An attachment's play restrictions ("Attach to a character you control", "Limit 1 per character") are card effects on the attachment itself. Write them with this.attachmentConditions({ … }), which creates these effects in a persistentEffect with location: Location.Any:

attachmentConditions propertyEffect
limit: numberattachmentLimit(limit)
myControl: trueattachmentMyControlOnly()
opponentControlOnly: trueattachmentOpponentControlOnly()
unique: trueattachmentUniqueRestriction()
faction: Faction | Faction[]attachmentFactionRestriction([faction].flat())
trait: string | string[]attachmentTraitRestriction([trait].flat())
limitTrait: { [trait]: number } | …[]one attachmentRestrictTraitAmount per entry
cardCondition: (card) => booleanattachmentCardCondition(cardCondition)

The control, unique, faction, trait and card-condition checks run in canAttach (playing or moving the attachment needs them) and again at every game state check: an attachment that no longer meets them is discarded with "… is discarded from … as it is no longer legally attached". The limits are only checked at the state check. The base canAttach accepts only characters; ProvinceAttachment replaces it and does not read these effects (it has controllerProvinceOnly() and unbrokenOnly() instead).

attachmentCardCondition(func) Card effect #

The attachment can only be on a character that passes func: "Character with printed [conflict-military] skill 3 or higher only."

ParameterTypeDefaultMeaning
func(card: DrawCard) => booleanrequiredCalled with the (prospective) parent.
 
// Dai Tsuchi: Restricted. Character with printed [conflict-military] skill 3 or higher only. …
this.attachmentConditions({
    cardCondition: (card) => card.printedMilitarySkill >= 3
});

Not used by any card directly; cards use attachmentConditions({ cardCondition }), e.g. Dai Tsuchi.

attachmentFactionRestriction(factions) / attachmentTraitRestriction(traits) Card effect #

"Attach to a [clan-lion] character", "Cavalry character only": the parent must have one of the listed factions or traits.

ParameterTypeDefaultMeaning
factionsFaction[]requiredThe parent must have at least one (isFaction).
traitsstring[]requiredThe parent must have at least one (hasTrait, lower case).
  • Each effect is checked on its own, so two effects (a faction and a trait) must both hold.
// Shori: Attach to a unique [clan-lion] character. …
this.attachmentConditions({
    unique: true,
    faction: 'lion'
});

Not used by any card directly; cards use attachmentConditions({ faction, trait }), e.g. Shori, Born in War.

attachmentLimit(amount) Card effect #

"Limit 1 per character": a character may hold at most amount copies of this attachment.

ParameterTypeDefaultMeaning
amountnumberrequiredHow many attachments with this card's id one character may hold.
  • Not checked when attaching. At the next state check the extra copies are discarded, oldest first, keeping the last amount attached.
  • Copies are counted by card id. With several limits, the highest wins.
// Way of the Dragon: Attach to a character you control. Limit 1 per character. …
this.attachmentConditions({
    limit: 1,
    myControl: true
});

Not used by any card directly; cards use attachmentConditions({ limit }), e.g. Way of the Dragon.

attachmentMyControlOnly() / attachmentOpponentControlOnly() / attachmentUniqueRestriction() Card effect #

"Attach to a character you control", "Attach to a character you do not control", "Attach to a unique character".

  • Control is compared between the attachment's controller (or the controller it will have once attached, e.g. when an attach gives control away) and the parent's controller.
  • Because they are rechecked at every state check, taking control of the parent can make the attachment illegal; it is then discarded.
// Sato: Peaceful. (…) Attach to a character you do not control. …
this.attachmentConditions({ opponentControlOnly: true });

Not used by any card directly; cards use attachmentConditions({ myControl, opponentControlOnly, unique }), e.g. Hawk Tattoo, Sato, Adorned Barcha.

attachmentRestrictTraitAmount(object) Card effect #

"Limit 1 Title per character": a character may hold at most n attachments with the trait.

ParameterTypeDefaultMeaning
objectRecord<string, number>requiredTrait to maximum, e.g. { title: 1 }.
  • Counts every attachment on the character with that trait, not only copies of this card. One attachment carrying the effect imposes the limit on all of them.
  • Not checked when attaching. At the next state check the oldest ones over the limit are discarded.
// Voice of the Ancestors: … It gains the Spirit trait and the text: "Limit 1 Spirit per character. …"
cardLastingEffect({
    canChangeZoneOnce: true,
    duration: Duration.Custom,
    effect: [
        blank(true),
        changeType(CardType.Attachment),
        addTrait('spirit'),
        attachmentRestrictTraitAmount({ spirit: 1 }),
        …
    ]
})

Used by Voice of the Ancestors; other cards use attachmentConditions({ limitTrait }), e.g. Shiba's Oath.

cannotHaveOtherRestrictedAttachments(card) Card effect #

"Attached character may not have other restricted attachments." An effect on the character, not on the attachment.

ParameterTypeDefaultMeaning
cardBaseCardrequiredThe one Restricted attachment that may stay (the effect's own card).
  • Not checked when attaching: at the next state check every other Restricted attachment on the character is discarded.
// Mirumoto Daishō: Restricted. Attached character may not have other restricted attachments. …

});

Used by Mirumoto Daishō

Restrictions

"Cannot" effects. Most are a Restriction stored under EffectName.AbilityRestrictions: a game action checks target.checkRestrictions(type, context) in its canAffect, so a restricted card is not a legal target and the action does nothing to it. A card's check also consults the restrictions on the acting player (playerCannot) and on the current conflict (charactersCannot).

cannotApplyLastingEffects(condition) Card effect #

Lasting effects of a kind can't be put on the card: "cannot have its skills reduced (… lasting effects …)".

ParameterTypeDefaultMeaning
condition(effect: EffectApplier) => booleanrequiredTrue for an effect that must not be applied.
  • Only cardLastingEffect reads it: matching effects are skipped, and the action can't affect the card at all when none of its effects could be applied.
  • Effects already on the card and persistent effects are untouched; Give No Ground adds suppressEffects for those.
// Give No Ground: Action: During a [conflict-military] conflict, choose a defending character you control -
// until the end of the conflict, that character gets +2[conflict-military] and cannot have its skills reduced. (…)
cardLastingEffect((context) => ({
    effect: [
        modifyMilitarySkill(2),
        suppressEffects((effect) => …),
        cannotApplyLastingEffects((effect) => effect && effect.isSkillModifier() &&
            ((effect.getValue() ?? 0) < 0 || effect.getValue(context.target) < 0))
    ]
}))

Used by Give No Ground, Festival of the Departed, Seasoned Patroller

cannotBeDeclaredAsAttacker() / cannotBeDeclaredAsDefender() Card effect #

"This character cannot be declared as an attacker / a defender."

  • Short for cardCannot(RestrictionType.DeclareAsAttacker) and cardCannot(RestrictionType.DeclareAsDefender). The check runs with the game's own context, not an ability's, so an appliesTo scope would not make sense.
  • Only declaration is blocked: the character can still be moved into the conflict or put into play in it. For "cannot participate" use cannotParticipateAsAttacker.
// Palace Guard: This character cannot be declared as an attacker against a less honorable player than you.
this.persistentEffect({
    condition: (context) => !!context.player.opponent && context.player.opponent.isLessHonorable(),
    effect: cannotBeDeclaredAsAttacker()
});

Used by Palace Guard, Aggressive Moto, Hiruma Yōjimbō, Tainted Hero

cannotParticipateAsAttacker(type?) / cannotParticipateAsDefender(type?) Card effect #

"This character cannot participate in conflicts as an attacker", "Attached character cannot participate in [conflict-military] conflicts."

ParameterTypeDefaultMeaning
typeConflictType | 'both''both'Which conflicts it covers.
  • Stronger than "cannot be declared": the character can't be declared, can't be moved to the conflict and can't be put into play in it on that side.
  • A character that is already participating when it gets the effect is sent home bowed at the next state check: "… cannot participate in the conflict any more and is sent home bowed".
  • A character with a dash in the conflict's skill can't participate either, with or without this effect.
  • For a printed ability, Shiba Peacemaker uses location: Location.Any so the effect is already there while the card is being put into play.
// Pacifism: Peaceful. (…) Attached character cannot participate in [conflict-military] conflicts.
this.whileAttached({
    effect: [
        cannotParticipateAsAttacker(ConflictType.Military),
        cannotParticipateAsDefender(ConflictType.Military)
    ]
});

Used by Pacifism, Shiba Peacemaker, Stolen Breath, Bayushi Traitor

cannotReceiveDishonorToken() / cannotReceiveHonorToken() / cannotReceiveTaintedToken() Card effect #

"Characters cannot receive dishonored status tokens", and the same for honored and tainted tokens.

  • Short for cardCannot(RestrictionType.ReceiveDishonorToken), ReceiveHonorToken and ReceiveTaintedToken. Read by dishonor, honor, taint, gainStatusToken, moveStatusToken and dishonorProvince.
  • An honored character can still be dishonored, and a dishonored one honored: that only removes the existing token, so no token is received.
// Steward of Law: While this character is participating in a conflict, characters cannot receive dishonored status tokens.
this.persistentEffect({

Duels

Duel effects apply to one duel. Put them on it with duelLastingEffect (the current duel, until it ends), typically from a duelChallenge or duelFocus ability. A duel effect in a persistentEffect reaches no duel and does nothing.

A side's duel total (Duel) is each participant's skill for the duel type, plus their modifyDuelistSkill for this duel, plus the side's modifyDuelTotal, plus the honor bid once bids are revealed. A duel effect (modifyDuelTotal) only reaches a duel through duelLastingEffect, which passes the duel as the target; the others are card effects on a participant.

Skills

A character's skill is built in this order (SkillCalculator.getSkillModifiers): the printed skill, changed by the base effects in the order they were applied (a setBase… or setBaseDash overrides every other base change); then, if any setMilitarySkill/setPoliticalSkill/setDash applies, the most recent one is the skill and nothing else counts; otherwise the modifiers are added (attachments' printed bonuses, modify…Skill, modifyBothSkills, status tokens), honor status rules adjust the status token modifiers, and the multipliers apply last, each to the running total. The result is floored at 0, and a dash counts as 0. All of these are card effects: use them in persistentEffect, whileAttached or cardLastingEffect.

A lasting effect that changes military or political skill can't be applied to a character with a dash in that skill (EffectApplier.canBeApplied), so such a character is not a legal target of cardLastingEffect for it. modifyBothSkills is only blocked when both skills are dashes. Persistent effects still reach the character, but the dash stays a dash.

Restrictions and immunity

A restriction (Restriction, effect name AbilityRestrictions) forbids something. It names what with cannot (a RestrictionType, or a PlayType to forbid playing that way) and, optionally, whose attempts it covers with appliesTo (a RestrictionScope, a { trait }, or an array of these, which must all match). The engine checks a restriction only where it calls checkRestrictions(type, context); every game action checks its own restriction type on each target, and targeting checks RestrictionType.Target. A restriction without cannot matches every check, including checks that name no type. cardCannot and charactersCannot are described with the first half of this page.

A card's check (BaseCard.checkRestrictions) also asks the acting player (context.player) and the current conflict, so a player restriction forbids that player from doing the thing to any card.

immunity(properties) Card effect #

"Immune to opponent's ring effects", "immune to events": the card can't be chosen as a target of, or affected by, anything from the given sources.

PropertyTypeDefaultMeaning
appliesToRestrictionScope | { trait: string } | (RestrictionScope | { trait: string })[]every sourceWhose effects the card is immune to. With an array, every entry must match.
cannotRestrictionType | PlayTypenone: everythingLimit the immunity to one kind of attempt. With it set, this is the same as cardCannot.
applyingPlayerPlayerthe effect's playerThe player that "opponent" and "own" scopes are measured from.
paramsunknownnoneExtra data for a scope, e.g. the card name for RestrictionScope.CopiesOfX.
  • Also accepts a bare RestrictionType or PlayType, which works like cardCannot(type) with no scope.
  • Immunity covers targeting (Target), every game action, and new effects: a persistent effect from an immune-to source isn't applied (RestrictionType.ApplyEffect is checked with that effect's context), and a lasting effect action can't affect the card.
  • "Immune to X and Y" needs two immunity effects; one effect with appliesTo: [X, Y] only matches sources that are both.
  • Common scopes: Events, OpponentsCardEffects, OpponentsRingEffects, CardEffectsExceptOwn, RingEffects.
// Isawa Kaede: Immune to opponent's ring effects. …
this.persistentEffect({
    effect: immunity({
        appliesTo: RestrictionScope.OpponentsRingEffects
    })
});
// Jak'ithith: … Immune to Corrupt and Mahō card effects. …
this.persistentEffect({
    effect: [
        immunity({ appliesTo: { trait: 'maho' } }),
        immunity({ appliesTo: { trait: 'shadowlands' } }),
        cannotReceiveTaintedToken()
    ]
});
